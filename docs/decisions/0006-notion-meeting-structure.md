# 0006. Notion 회의록 구조 설계 (W7 착수)

- 날짜: 2026-08-25
- 상태: 채택, DB 구조 생성 완료 (동기화 코드는 아직)

## 맥락

M2~M3 순서 3번(Notion 결정 기록 동기화). 오너는 회사·회의 경험이 없어 "최대한 많이 질문해서 같이 설계해달라"고 요청함. 대화로 확인한 것:

- 회의는 3갈래: **CozyHaus**(경석님 또는 와이프와), **Bon Sushi**(파트너 누나들과), **소셜미디어 기획**(경석님과, 두 매장 공통)
- 회의 목적 4가지: ①지표분석 ②지난 액션플랜 리뷰 ③다음 액션플랜(담당자·기한, 캘린더 연동 희망) ④소셜미디어 콘텐츠 계획(기획/촬영/편집 담당자 각각 다름, 목표 품목·기대효과 기록)
- 녹음→회의록 자동화는 원함(Gemini로 가능, Notion 유료 AI 불필요)이나 **지금은 보류** — DB 구조부터 안정화 후 추가
- Notion은 경석님·파트너 누나들도 **직접 접근**해서 쓸 예정 → 담당자 필드는 Notion "Person" 속성(실제 멤버 @멘션)으로 설계
- 구글 리뷰 데이터는 코덱스 사이드 프로젝트 소관(`docs/decisions/0005`)이라 지금은 못 가져옴 — 나중에 두 프로젝트가 데이터 공유하게 되면 추가 검토

## 결정 — Notion 구조 5개 DB

오너가 공유한 페이지("Golden Tree 회의", page_id `3c7aacc8-b80e-8042-a66c-dfd819894360`) 아래 생성:

| DB | page_id | 용도 |
|---|---|---|
| CozyHaus 회의록 | `3c7aacc8-b80e-81de-9112-f278996687ea` | 회의 1건=1행. 날짜·참석자·자동 지표 요약·특이사항 |
| CozyHaus 액션아이템 | `3c7aacc8-b80e-81d5-a75f-e015bf138464` | 할 일 1건=1행. 담당자·기한·상태, 회의록과 relation |
| Bon Sushi 회의록 | `3c7aacc8-b80e-8132-a6c8-cae68dde981d` | 위와 동일 구조 |
| Bon Sushi 액션아이템 | `3c7aacc8-b80e-81cf-9ffc-f83d9b69d040` | 위와 동일 구조 |
| 소셜 콘텐츠 캘린더 | `3c7aacc8-b80e-8119-969e-e92e4617889c` | 매장 공용. 기획/촬영/편집 담당자·일정 각각, 목표 품목, 기대 효과, 게시 후 결과 |

회의록/액션아이템을 매장별로 나눈 이유: 참석자 그룹 자체가 다르고(경석·와이프 vs 파트너 누나들), 서로의 회의 내용을 볼 필요가 없어서. 소셜 콘텐츠 캘린더는 경석님이 두 매장을 다 담당해서 하나로 유지(매장 select 필드로 구분).

`NOTION_API_TOKEN`을 Supabase 시크릿으로 등록함.

## 다음 단계 (아직 안 함)

1. 소셜 콘텐츠 캘린더의 "목표 품목"·"게시 후 결과"를 `analytics_post_item_sales_trend`/`analytics_social_sales_correlation`과 연결하는 동기화 (게시 완료로 바뀌면 자동으로 결과 채워주기)
2. 회의록의 "지표 요약"을 회의 전 자동으로 채워주는 동기화 (analytics_dispatch 호출)
3. 액션아이템 → 아이폰 캘린더 연동(ICS 피드 자체 제작 — Notion 자체 기능으로는 안 됨)
4. Discord `/ask`에서 액션아이템·회의록 조회 가능하게 (Query Contract 확장)
5. 녹음→회의록 자동화 (Gemini 오디오 이해 활용, 보류 중)

## 결과 (사후 기록)

DB 5개 생성 완료. 처음에 relation을 `single_property`(단방향)로 만들어 회의록 쪽에서 액션아이템이 안 보이는 문제가 있었음 — `dual_property`(양방향)로 수정하고, 회의록 DB에 "액션아이템 개수" 롤업(rollup) 추가.

오너 피드백 — "유튜브에서 본 것보다 단순해 보인다": Notion API는 데이터베이스·속성·relation·rollup까지는 만들 수 있지만 **뷰(칸반보드/캘린더 레이아웃)는 API로 설정 불가** — Notion 자체 제약. 액션아이템 DB는 칸반보드(Group by 상태), 소셜 콘텐츠 캘린더는 캘린더 뷰(게시 예정일 기준)를 오너가 직접 몇 번의 클릭으로 추가하도록 안내함.
