# 0019. AI 제공자 Gemini → OpenAI 전환

- 날짜: 2026-09-09
- 상태: 채택

## 맥락

주간 OKR 특이사항 문장(`0018`)에서 오너가 대시보드에 "본스시는 포스팅 관련 데이터가 없어 원인을 확인할 수 없다"는 문장을 보고 문의 — 실제로는 그 주 내내 매일 포스팅이 있었음(별도로 조회 실패를 조용히 삼키던 버그로 판명, 이 문서 하단 및 `0018` 참고). 이 조사 과정에서 재현 테스트를 반복하다 Gemini 무료 티어의 **일일 20건 요청 한도**(`gemini-3.6-flash`)에 실제로 걸림 — Discord 봇(질문 1건당 최대 8번 반복 호출)과 주간 스냅샷 cron이 같은 모델/키를 공유해서, 평소 사용량만으로도 자주 막힐 수 있는 구조적 문제로 확인됨.

오너가 이미 ChatGPT/Claude 최저 유료 요금제를 구독 중이라며 "그럼 그걸로 하는 게 낫지 않냐"고 제안. 대화 중 확인된 사실: 소비자용 구독(ChatGPT Plus 등)은 API 사용량과 별개 — API는 항상 별도 결제 계정이 필요함(오너에게 설명·정정). 가격 조사 결과 OpenAI 저가형(GPT-5.6 Luna, $0.20/$1.20 per 1M 토큰)이 Gemini Flash($0.75/$3.75)보다도 저렴했고, Gemini 같은 "매일 리셋되는 무료 한도" 구조 자체가 없음(신규 계정 일회성 체험 크레딧만 있고 이후는 바로 종량제). 오너 최종 결정: 급하지 않지만 장기적으로 유리하니 지금 전환.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| Gemini 유료 티어로 전환(모델 유지) | 코드 변경 없음, 즉시 해결 | 이번 조사에서 드러난 Gemini 특유의 wire-format 버그(role 이름, thought_signature 등)는 그대로 남음 |
| OpenAI(GPT-5.6 Luna)로 전환 | 더 저렴, 무료-한도 구조 없음, 표준적인 tool-calling 형식(Gemini 특수 처리 불필요), 오너가 이미 결제 경험 있는 제공자 | 디스코드 봇·주간 특이사항·Meta 비전 설명 3곳 모두 코드 재작성 필요, 재검증 필요 |
| Claude로 전환 | 함수 호출 안정성 평가 좋음 | 가격이 셋 중 가장 높음($1.00/$5.00), 이번엔 오너가 GPT를 지목 |

## 결정

**OpenAI `gpt-5.6-luna`로 전량 전환.** 대상 3곳 전부:
1. `runtime/discord/src/index.ts` — `/ask` 봇의 멀티스텝 도구 호출 루프
2. `sync/weekly-okr-snapshot/src/index.ts` — 주간 특이사항 문장 생성
3. `sync/meta/src/index.ts` — 포스팅 사진/영상 AI 설명(Vision)

API는 Chat Completions(`/v1/chat/completions`)를 쓴다(Responses API도 지원되지만, 기존 코드 구조(messages 배열 + tool_calls)와 가장 가깝고 문서화가 안정적인 표준 형식이라 이걸 선택). `gpt-5.6-luna`는 도구(tools)를 넘길 때 `reasoning_effort`를 명시적으로 `"none"`으로 두지 않으면 400 에러가 난다(실제 확인, 기본값 `medium`이 함수 호출 미지원) — 세 곳 모두 항상 `reasoning_effort: "none"`을 명시한다(저지연·저비용 용도라 별도 reasoning 단계 불필요).

Gemini 특유의 특수 처리(functionCall의 thought_signature 보존, role을 "user"로 우회하는 것 등, `0013`)는 전부 제거 — OpenAI는 표준 `tool_calls`/`role:"tool"`/`tool_call_id` 형식을 그대로 쓴다.

`GEMINI_API_KEY` 시크릿은 삭제(레포 전체에서 참조 없음을 grep으로 확인 후 삭제). `OPENAI_API_KEY` 신규 등록(오너가 결제수단 등록 후 발급, 초기 충전 $10 + 오토리로드, 월 재충전 한도는 폭주 방지용 안전장치로 $100 대신 낮춰 설정 권고).

## 근거

- 가격: 세 후보 중 OpenAI 저가형이 가장 저렴하고, 우리 실사용량(하루 20~30건)으로는 어느 쪽이든 월 몇 달러 수준이라 가격 차이 자체는 결정적 요인이 아니었음 — 결정적인 건 Gemini의 "매일 리셋되는 무료 한도" 구조가 아예 없다는 점(운영 리스크 제거)
- 표준 wire format: 이번 세션에서 겪은 Gemini 관련 버그 상당수(역할 이름 오류, thought_signature 누락 400, 조용한 오류 삼킴으로 인한 오판)가 이 API 특유의 까다로움과 무관하지 않았음 — OpenAI의 훨씬 널리 쓰이는 표준 형식으로 옮기면 유지보수 리스크가 줄어들 것으로 판단
- 오너가 이미 결제 계정을 보유한 제공자를 선호(결정 과정 투명성 — 오너 스스로 가격 비교 후 선택)

## 결과 (사후 기록)

`discord-bot` v26, `weekly-okr-snapshot` v5, `meta-sync` v10 배포. 배포 전 curl로 직접 검증:
- 디스코드 봇 멀티스텝 루프: 질문→tool_calls→가짜 tool 응답→최종 한국어 답변까지 전체 왕복 확인
- 주간 특이사항: 실제로 재실행해 양쪽 매장 모두 포스팅 인용 포함 정상 문장 생성 확인
- Meta 비전 설명: 이미지 base64 입력→한국어 설명 생성 확인

부수적으로 `0018`의 "포스팅 데이터 없음" 오판 버그(조회 실패를 조용히 null로 삼키던 문제)도 같은 세션에서 함께 수정됨 — 이 버그 자체는 모델 제공자와 무관한 별개 결함이었으나, 재현 조사 중 Gemini 쿼터 문제를 같이 발견하며 이 결정으로 이어짐.
