# 0011. 레시피 원가율 감시 시스템

- 날짜: 2026-08-25
- 상태: 채택 (스키마 완료, 영수증 OCR 파이프라인·초기 레시피 입력 진행 중)

## 맥락

오너가 지금까지 "이제 슬슬 가격을 올려야 되는거 아냐?"를 감으로 판단해왔는데, 이걸 데이터 기반으로 바꾸고 싶어함. 레시피(재료+수량+생산량+제조시간)를 데이터화하고, 영수증을 올릴 때마다 재료 단가를 갱신해서, 재료원가율이 기준을 넘으면 Discord로 알리는 시스템을 요청.

명시적으로 범위 밖: 북키핑(비용 기장)은 QuickBooks로 별도 진행 중 — 이 시스템은 재료 단가 갱신·원가율 감시 전용이며 지출 승인(G2)이나 회계(G3) 대상이 아니다.

## 결정 (오너 확인 완료)

| 항목 | 결정 |
|---|---|
| 레시피 초기 입력 | 대화로 하나씩(오너가 말하면 구조화해서 저장). 스프레드시트 일괄 입력 아님 |
| 원가율 기준 | **재료원가만** 대상. 기본 25%, 품목별로 오너가 개별 조정 가능(예: 마카롱은 인건비가 많이 들어 20%로 낮춤) |
| 인건비 처리 | 자동 알림 계산엔 안 씀. `prep_time_minutes`로 참고 기록만 하고, 오너가 그 정보를 보고 target_cost_ratio를 직접 낮추는 방식으로 반영 |
| 알림 조건 | **연속 30일** 내내 기준 초과해야 알림(하루 반짝 초과는 무시 — 재료값 변동성 감안) |
| 시작 범위 | 잘 팔리는 메뉴 몇 개부터(전체 메뉴 일괄 아님). Square 매출 데이터로 실제 베스트셀러 확인 후 제안 |

## 스키마 (`db/migrations/0014`)

- `ingredients` / `ingredient_price_history` — 재료 마스터+단가 이력. 최신 구매가가 그대로 `current_unit_price`(스무딩 없음)
- `receipts` / `receipt_line_items` — 영수증 원본(이미지+OCR 결과) + 품목별 매칭 상태. `confirmed=true`가 되기 전까진 단가에 반영 안 됨(오검출 방지)
- `recipes` / `recipe_ingredients` — 품목별 레시피
- `recipe_cost_current`(뷰) — 현재 단가 기준 실시간 원가율
- `recipe_cost_daily_snapshots` / `recipe_cost_alerts` — 연속 30일 판단용 일별 적재 + 중복 알림 방지(레시피당 미해결 알림 1건 제한)

## 근거

- "스무딩 없이 최신가"로 결정한 이유: 오너가 이미 "버터값 오르내림"을 알고 있고, 그 변동성 흡수는 스무딩이 아니라 "연속 30일" 판단 로직이 담당하도록 역할을 분리 — 단가 자체는 항상 정직한 최신값으로 유지
- 인건비를 자동 계산에 안 넣은 이유: 인건비 반영 공식(시급 기준 등)을 만들면 그 공식 자체가 또 하나의 판단 대상이 됨 — 대신 오너가 이미 알고 있는 "이 메뉴는 손이 많이 간다"는 감각을 target_cost_ratio 조정이라는 단순한 손잡이로 직접 반영하게 함
- 확정된 미해결 알림 1건 제한: 30일 이상 계속 초과 상태일 때 매일 알림이 오면 무시하게 될 위험 — 한 번 알리고, 기준 밑으로 내려갔다가 다시 30일 채워야 재알림
