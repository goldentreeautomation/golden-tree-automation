# 0017. Discord 봇 RPC 타임아웃이 전체 기간 조회엔 너무 짧았음

- 날짜: 2026-09-08
- 상태: 채택

## 맥락

오너가 `/ask`로 "본스시 술 판매 비중이 몇퍼센트야 지금까지"라고 물었더니 `AbortError: The signal has been aborted`로 실패. 원인 조사.

## 원인

`analytics_category_sales`를 전체 기간(2025-06~2026-09)으로 호출하면 실측 약 21.5초 걸림(`EXPLAIN ANALYZE`로 확인) — 직전에 무한 대기 버그(`0013` 다섯 번째 발견)를 고치며 넣은 RPC 타임아웃이 20초였어서, 정상적으로 느릴 뿐인 조회까지 중간에 끊겼다.

`EXPLAIN ANALYZE`로 확인한 병목: `order_items_enriched` 뷰가 카탈로그 체인(품목→옵션→카테고리) 3단 조인을 하는데, 본스시 전체 기간이면 `order_items` 18만여 행 중 6만9천여 행을 훑어야 해서 Seq Scan+Hash Join에 시간이 걸림. `ANALYZE`로 통계 갱신해봤지만 플랜/시간에 유의미한 변화 없음 — 데이터 규모 자체의 문제라 인덱스 튜닝만으로는 크게 안 줄어듦.

## 결정

1. RPC 타임아웃 20초 → **45초**로 상향(`runtime/discord/src/index.ts`). 실측 21.5초에 여유를 더함.
2. 타임아웃이 나도 원인 불명의 `AbortError` 대신 "기간이 너무 넓을 수 있다"는 명확한 한국어 메시지로 바꿔, Gemini의 자체 시행착오 루프(`0013`)가 기간을 좁혀 재시도하도록 유도.
3. 전체 기간 스캔이 근본적으로 느린 문제 자체는 이번엔 안 고침 — 인덱스만으론 크게 개선 안 되고, 매출 요약용 집계 테이블(materialized view) 같은 구조적 변경이 필요한데 지금은 우선순위 낮음(전체 기간 질문 빈도가 아직 낮음).

## 결과 (사후 기록)

`discord-bot` v21 배포. 실제 질문("본스시 술 판매 비중")은 직접 조회로 확인: 전체 기간 순매출 대비 **0.76%**($5,921.60 / $782,489.88, 병맥주·사케 기준 — 카테고리 태그가 없어 품목명으로 식별함). 카테고리 체계에 "주류" 구분이 없다는 것도 이번에 확인(추후 필요하면 카탈로그에 카테고리 추가 검토).
